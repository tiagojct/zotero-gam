# gam Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Zotero 10 plugin that shows the Obsidian vault facts of each item (column, item pane section, "Cited in") and creates literature notes in the Sub-Sub format.

**Architecture:** Pure logic lives in ES modules under `content/lib/` with no Zotero or browser globals, so Node tests import them directly. Zotero code (`content/vault.mjs`, `content/ui/*.mjs`, `content/gam.mjs`) takes `Zotero` and `IOUtils` from the plugin scope and calls the pure modules. `bootstrap.js` registers chrome, imports `content/gam.mjs` and calls its hooks.

**Tech Stack:** Zotero 10 bootstrap plugin, plain JavaScript (ES modules), Fluent .ftl, Node 22 `node:test` for unit tests. No npm dependencies.

**Spec:** `docs/superpowers/specs/2026-11-14-gam-design.md`

## Global Constraints

- Zotero 10.0.9. manifest `strict_min_version: "10.0"`, `strict_max_version: "10.*"`.
- Plugin id: `gam@tiagojct.eu`.
- APIs: `Zotero.ItemTreeManager.registerColumn`, `Zotero.ItemPaneManager.registerSection`, `Zotero.MenuManager` (target `main/library/item`). The JSDoc is in the app bundle. Read it with: `mkdir -p /tmp/zapi && unzip -o -q /Applications/Zotero.app/Contents/Resources/app/omni.ja 'chrome/content/zotero/xpcom/pluginAPI/*' -d /tmp/zapi`.
- The plugin never changes or overwrites an existing vault file. It only creates new files.
- Vault default `~/quarterdeck/powerslave`; literature folder `sub-sub/literature`; "Cited in" leaves out `archive`, `.obsidian`, `.trash`.
- Obsidian URI: `obsidian://open?vault=<vault>&file=<path from vault root, without .md, encodeURIComponent>`. Vault names compare without case.
- Zotero URI in notes: `zotero://select/library/items/<KEY>`.
- Citekey: native `citationKey` field, else a `Citation Key: ...` line in Extra.
- Paths and citekeys are compared after NFC normalisation.
- File and folder names: lowercase, hyphens, no accents. No emojis in files or commits. Commits: author Tiago Jacinto, no Claude lines.
- Replies and files in ASD-STE100 Simplified Technical English.

## Review Focus

1. A vault note with no frontmatter, a BOM, CRLF line ends or broken YAML: the note is indexed with empty metadata; no exception. Test in Task 1.
2. A title or venue with quotes, colons, `#` or a newline: the new note has valid frontmatter that `parseFrontmatter` reads back with the same values. Test in Task 4.
3. An item with no creators, no date and no DOI: `baseKey` gives the anon/nd form and the template leaves out `doi`. Tests in Tasks 2 and 4.
4. The vault folder is missing or not readable: the column is empty, the pane says "Vault folder not found: <path>", and Zotero logs one line, not one line for each row. Manual check in Task 9.
5. A file name in NFD form (macOS) against a citekey in NFC: the note is found. Test in Task 5.

- Only regular items (`item.isRegularItem()`); else throw "Notes can only be made for regular items.".
- No citekey: `uniqueKey(baseKey(json), taken)` where `taken` is the citekeys of all library items plus `index.citekeys()`. Write it with `item.setField("citationKey", key)` and `await item.saveTx()`. If the field is not valid for the item type, add a `Citation Key: <key>` line to Extra instead.
- `createFile(PathUtils.join(vault, ...literatureFolder.split("/"), citekey + ".md"), noteFromItem(...))`. On "file exists", show "A note with this name exists: <path>. Nothing was written." and stop.
